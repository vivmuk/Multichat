# Surface brief — V's MultiGen AI Chat (catalogue first; chat, benchmark and API guide inherit)

**Mode:** Operate. The visitor completes a task: find the model that meets the constraints, then use it. Dense data, phone and desk.

**Who, what job, what action:** Vivek, browsing 366 models with an API key in hand. Job: narrow the catalogue to what is actually available to him, read a model's standing honestly, and send it to work. Action: open the catalogue, set the facets, read the cards, take one to the chat.

**Proof and content on hand:** the live catalogue with 366 rows (134 video, 41 image, plus text, voice, music), the hand-curated policy ratings with live filter counts, the benchmark page, the API guide, the committed icon set. No prices, no user counts, no benchmark claims beyond what the app itself runs.

**Constraints:** preserve every function and control exactly; the phone is a real surface; policy wording stays honest ("Allowed" means not blocked, never guaranteed); the API key is never echoed anywhere; four pages share one world.

## Direction contract

**THESIS.** The catalogue is a wooden card-catalogue in a reading room: pull a drawer, thumb the guide tabs, read a typed card, stamp it, and send a request slip. It refuses the category default both ways — not the dark neon dashboard with glowing pills, and not the white docs page with a sidebar. The one idea: *a model is a card you can read at a glance and file under what you will actually do with it.*

**OWN-WORLD.** With every word removed you would still see it: oak and warm brass framing a ground; cream cards with a ruled top line and a punched hole; guide tabs that stand proud of the card stack with a facet printed on each; typed lines for the attributes; a red stamp for a policy rating and a blue stamp for a heading; the drawer pull at the page's edge. Nothing glows; the light comes from the room, and shadows are the drawers' own depth.

**STORY.** *Understand:* each card is one model, and the drawer says how many are left in it. *Believe:* the ratings are stamped honestly, and nothing claims more than it can show. *Do:* set the tabs, read the cards, take one to the chat.

**FIRST VIEWPORT.** The cabinet is open: a brass-ruled header with the app's true name and the icon, the drawer face carrying the facet tabs (type, policy axis) each showing its count, the search field set as the drawer's label line, and below it the card stack — several cards visible as cards, the first one fully readable: model name, its id, capability lines, and its stamped ratings. The phone shows the same stack one card wide.

**FORM.** Assigned by the roll: candidate 6 of my grounded list (seed key `338f07ba`), built code-led.

**RAISES** (the discipline each dealt challenger held that this direction lacked; none wears a challenger's clothes):
- from the oscilloscope bench: *a measured grid where every division means something* — the attribute table is a real grid with its units in the header, and the counts are read off it.
- from the Kraftwerk grid: *a connector that lights as the route becomes active* — the path from a chosen card to the chat is drawn and lights when the model is sent.
- from the cassette deck: *every function gets its own labelled switch* — each filter axis is a panel switch whose state is printed on it, not an unlabelled dropdown.
- from the cracktro queue: *state as a step, not a colour* — a model's standing is carried by weight, letterspacing and the stamp, so it survives greyscale and colour-blindness.

**FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.
